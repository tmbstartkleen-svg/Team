# Unified project workspace launch plan

Owner authorized combining the projects into an ATLAS-coordinated experience. **Implementation stage: common registry and proposal routing**. This is a logical unification, not a physical repository merge.

## Protected source projects
The registry includes all fifteen discovered GitHub repositories: Team, Safeguard, Edgeforce-AI, Claude_Sports, Claude_Sports_TMB, Grok_Sports, Gemini-Sports, Counter, fee-fi-beta, Shiftproof, TravAI, santera, santera-free-fixed, Santera-7 and Santera-v-3. No repo is deleted, moved or merged. Unknown Santera relationships must be verified before consolidating versions.

## ATLAS owner experience
- One command center with filtering for security, sports, business, business-review and core projects.
- Six primary persona leads: MBA Business & Academia; Sports Guru; AL AI Content Analyst; FSQA Manager; Regional Sanitation Manager; Coding & Execution Lead. FSQA and AL support cross-project review.
- Each workspace has its own source history, permissions, connection status, limits, evidence, tasks and execution ledger.
- Workspace assignments are **proposals** until server-verified authorization, real tool adapter and durable action receipts exist.
- Do not represent all repositories as connected tool executors merely because they are listed in a workspace.

## Next certification gates
1. Deploy isolated read-only registry UI in authorized staging and verify no data leakage.
2. Connect repository health/usage through owner-authorized read adapters with caching and rate limits.
3. Implement persistent scoped grants per repository, project and tool; confirm denial behavior.
4. Wire verified specialist tasks to execution ledger with recovery, idempotency and emergency stop.
5. Integrate consent-based learning retrieval and evaluation promotion into a versioned D1-backed store.
6. Install/check an offline model and local compiler/runtime on Mac; prove network-disconnected coding tests.
7. Verify Safeguard's independently scoped read-only feed and ensure existing Mac sensor continuity.
8. Cure Vercel resource provisioning failure or use approved Cloudflare staging path, then certify production gates.

**Explicit no-op boundaries:** no GitHub merges, migrations, repository deletion, DNS changes, deployment, secret transfer, privileged command execution, or approval of `cert-github-read-20261019-v2`.
