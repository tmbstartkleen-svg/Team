## Continuous improvement design
1. Capture approved owner feedback, checked source material and verified action outcomes as **proposals**.
2. Record sources, timestamps and relevant specialist. Never ingest passwords, API keys or personal secrets.
3. Evaluate against a versioned benchmark suite for correctness, security and regressions.
4. Require owner approval before promoting a new memory, instruction, tool policy or model.
5. Preserve version history, revocation, rollback and ability to erase retained learning.
6. Re-evaluate after verified provider/model releases, not on an assumed release schedule.

This architecture provides **feedback-based learning** through memory, retrieval and validated updates. It does **not** continuously retrain model weights or promise improvement without tests. Do not silently learn from unverified web content, model outputs, private mail or arbitrary attachments.

## Premium model routing
- Select the most capable **available, connected, owner-allowed** hosted model for high-complexity work, considering quality, latency and cost limits.
- Use an explicitly installed and approved local inference model for offline tasks. Local availability does not imply parity with the strongest hosted models.
- Report actual model name/provider/version with execution receipts. No hypothetical GPT variant, synthetic benchmark or simulated run may be presented as a real connected model.
- Keep data within authorized provider and privacy boundaries; secret values stay in server-side storage.
- Fail closed rather than silently change provider, overrun budgets or execute unauthorized actions.
